# Гипотезы для A/B-тестов

## Цель экспериментов

Задача экспериментов — повысить количество бронирований за счёт улучшения
наиболее значимых пользовательских сценариев. Приоритет получают сегменты, в
которых одновременно наблюдаются большой объём активности и заметный потенциал
роста конверсии.

## Приоритет гипотез

| Приоритет | Гипотеза | Основание для проверки |
|---|---|---|
| 1 | Упростить мобильный сценарий бронирования | Мобильная конверсия ниже десктопной, и разрыв сохраняется во времени |
| 2 | Персонализировать порядок гостиниц для канала 9 | Канал формирует основную часть активности, поэтому даже небольшой рост даст заметный эффект |
| 3 | Упростить мобильное пакетное бронирование | Конверсия мобильных пакетных событий составляет 2,45% против 4,82% на немобильных устройствах |
| 4 | Помочь пользователям со сложными поездками вернуться к выбору | Конверсия снижается при раннем планировании и длительном проживании |
| 5 | Добавить стимул к раннему бронированию | Поездки через 31+ день конвертируются хуже поездок с коротким сроком планирования |
| 6 | Напомнить о повторном бронировании через год | У зрелых когорт заметен рост повторных бронирований примерно через 12 месяцев |
| 7 | Персонализировать порядок гостиниц на рынках 661 и 710 | Рынки дают большой объём событий, но их конверсия не максимальна |
| 8 | Проверить масштабируемость канала 4 | Канал имеет наиболее высокую конверсию, но существенно меньший объём |

## 1. Упрощённый мобильный сценарий бронирования

### Наблюдение

Конверсия на мобильных устройствах ниже, чем на десктопных. Разрыв сохраняется
во времени, а вклад мобильных устройств в бронирования ниже их доли в общей
активности.

### Гипотеза

Если сократить количество шагов мобильного бронирования, сохранять введённые
данные и сделать кнопку целевого действия более заметной, то мобильная
конверсия в бронирование увеличится.

### Дизайн эксперимента

- Сегмент: все пользователи, бронирующие с мобильных устройств.
- Контрольная группа: текущий мобильный сценарий.
- Тестовая группа: сокращённый сценарий с сохранением введённых данных и более
  заметной кнопкой целевого действия.
- Единица рандомизации: пользователь.
- Основная метрика: конверсия в бронирование.
- Дополнительные метрики: время до бронирования и доля прерванных сессий.
- Защитные метрики: скорость загрузки и количество технических ошибок.

## 2. Персонализированный порядок гостиниц для канала 9

### Наблюдение

Канал 9 формирует основную часть активности. Благодаря большому объёму даже
небольшой рост его конверсии может дать заметный прирост бронирований.

### Гипотеза

Если для пользователей канала 9 поднимать в результатах поиска гостиницы,
которые чаще бронировали пользователи с похожими параметрами поездки —
направлением, сроком до заезда, длительностью проживания, составом группы и
устройством, — то конверсия канала увеличится.

### Дизайн эксперимента

- Сегмент: пользователи канала 9.
- Контрольная группа: текущий порядок гостиниц.
- Тестовая группа: персонализированный порядок с учётом параметров поездки.
- Единица рандомизации: пользователь.
- Основная метрика: конверсия в бронирование.
- Дополнительные метрики: количество бронирований, глубина просмотра и доля
  сессий с бронированием.
- Защитные метрики: скорость формирования результатов и разнообразие
  предложений.

## 3. Упрощённое мобильное пакетное бронирование

### Наблюдение

Пакетные поездки формируют 24,48% событий, но только 13,53% бронирований. Их
общая конверсия составляет 4,43% против 9,17% для бронирований только отеля.
Особенно заметен разрыв на мобильных устройствах: 2,45% против 4,82% на
немобильных. Канал 9 формирует 56,54% всех пакетных событий, поэтому тест
целесообразно начинать с его мобильного трафика.

### Гипотеза

Если сократить количество шагов мобильного пакетного бронирования и на каждом
этапе показывать заметную сводку выбранных компонентов, итоговой стоимости и
условий отмены, то конверсия мобильного пакетного поиска увеличится.

### Дизайн эксперимента

- Сегмент: мобильные пользователи канала 9, выбирающие пакетную поездку.
- Контрольная группа: текущий мобильный сценарий.
- Тестовая группа: сокращённый сценарий с постоянной сводкой пакета.
- Единица рандомизации: пользователь.
- Основная метрика: конверсия мобильных пакетных событий в бронирование.
- Дополнительные метрики: время до бронирования, доля пользователей, дошедших
  до финального подтверждения, и доля прерванных сессий.
- Защитная метрика: скорость загрузки.

## 4. Сохранение поиска для сложных поездок

### Наблюдение

Чем раньше планируется поездка и чем дольше проживание, тем ниже конверсия. Для
поездок через 0–1 день она составляет 10,98%, а через 91+ день — 3,01%. Для
одной ночи конверсия равна 9,43%, а для 15+ ночей — 1,72%. Самый сложный
сценарий — поездка через 91+ день на 15+ ночей с конверсией 1,05%.

### Гипотеза

Если пользователям, которые планируют поездку заранее или выбирают длительное
проживание, предложить сохранить поиск и получать уведомления об изменении
цены, то они будут чаще возвращаться к выбору и завершать бронирование.

### Дизайн эксперимента

- Сегмент: пользователи со сроком до поездки 31+ день и/или длительностью
  проживания 8+ ночей.
- Контрольная группа: текущий сценарий поиска.
- Тестовая группа: сохранение поиска и уведомления об изменении цены.
- Единица рандомизации: пользователь.
- Основная метрика: доля пользователей, совершивших бронирование в течение
  30 дней после первого поиска в выбранном сегменте.
- Дополнительные метрики: доля сохранённых поисков, возврат к поиску и
  конверсия вернувшихся пользователей.
- Защитные метрики: отключение уведомлений и отмены бронирований, если данные
  об отменах будут доступны.

## 5. Стимул к раннему бронированию

### Наблюдение

Конверсия снижается по мере увеличения срока до поездки: для поездок через
0–1 день она составляет 10,98%, а для поездок через 91+ день — 3,01%.

### Гипотеза

Если при планировании поездки через 31+ день заметнее показывать доступные
условия бесплатной отмены, возможность фиксации цены или предупреждение об
изменении доступности, то конверсия в раннее бронирование увеличится.

### Дизайн эксперимента

- Сегмент: пользователи, планирующие поездку через 31+ день.
- Контрольная группа: текущая подача условий бронирования.
- Тестовая группа: заметное отображение реально доступных стимулов к раннему
  бронированию.
- Единица рандомизации: пользователь.
- Основная метрика: конверсия в бронирование.
- Дополнительные метрики: время от первого поиска до бронирования и доля
  пользователей, вернувшихся к поиску.
- Защитные метрики: отмены бронирований и маржинальность, если необходимые
  данные будут доступны.

## 6. Персонализированное напоминание о повторной поездке

### Наблюдение

У ряда зрелых когорт после снижения повторных бронирований в первые месяцы
наблюдается заметный рост примерно через 12 месяцев после первого
бронирования. Это может указывать на годовую периодичность спроса.

### Гипотеза

Если пользователям, которые совершили первое бронирование около 11 месяцев
назад и с тех пор не бронировали повторно, отправить персонализированное
напоминание, то доля повторных бронирований на 12-м месяце увеличится.

### Дизайн эксперимента

- Сегмент: пользователи с первым бронированием 11 месяцев назад без повторных
  бронирований после него.
- Контрольная группа: без напоминания.
- Тестовая группа: персонализированное напоминание с учётом предыдущего
  направления и параметров поездки.
- Единица рандомизации: пользователь.
- Основная метрика: доля пользователей с бронированием в течение 30 дней после
  отправки напоминания.
- Дополнительные метрики: переход по напоминанию и начало нового поиска.
- Защитные метрики: отписки и отключение уведомлений.

## 7. Персонализированный порядок гостиниц на рынках 661 и 710

### Наблюдение

Рынки 661 и 710 дают большой объём событий, но их конверсия составляет 4,62%
и 4,17% соответственно. Даже небольшой прирост конверсии в этих сегментах
может обеспечить значительное количество дополнительных бронирований.

### Гипотеза

Если на рынках 661 и 710 поднимать в результатах поиска гостиницы, которые
чаще бронировали пользователи с тем же направлением и похожими параметрами
поездки, то конверсия увеличится за счёт более высокого положения релевантных
предложений.

### Дизайн эксперимента

- Сегмент: пользователи рынков 661 и 710.
- Контрольная группа: текущий порядок гостиниц.
- Тестовая группа: персонализированный порядок с учётом направления, срока до
  поездки, длительности проживания, состава путешественников и устройства.
- Единица рандомизации: пользователь.
- Основная метрика: конверсия в бронирование.
- Дополнительные метрики: количество бронирований, глубина просмотра и доля
  сессий с бронированием.
- Защитные метрики: скорость формирования результатов и доля поисков без
  доступных предложений.

## 8. Масштабирование канала 4

### Наблюдение

Канал 4 показывает наиболее высокую конверсию, но имеет существенно меньший
объём активности. До запуска эксперимента необходимо определить фактический
источник и стоимость этого трафика.

### Гипотеза

Если увеличить объём привлечения через канал 4, то количество бронирований
вырастет при сохранении приемлемой конверсии и стоимости привлечения одного
бронирования.

### Дизайн эксперимента

- Подготовка: определить источник канала 4 и получить данные о расходах на
  привлечение.
- Тестовый сегмент: ограниченная аудитория, для которой увеличивается объём
  трафика из канала 4.
- Контрольный сегмент: сопоставимая аудитория с текущими условиями привлечения.
- Основная метрика: прирост количества бронирований.
- Контрольная метрика: конверсия канала 4 не должна существенно снизиться.
- Бизнес-метрика: стоимость привлечения одного бронирования.

## Общие правила проведения тестов

- Пользователь должен оставаться в одной экспериментальной группе во всех
  своих сессиях.
- Основная метрика и минимальный значимый эффект фиксируются до запуска.
- Длительность теста рассчитывается по размеру сегмента и текущему значению
  основной метрики; тест должен охватывать не менее двух полных недельных
  циклов.
- Результаты анализируются по исходному распределению пользователей между
  группами, без исключения участников после начала эксперимента.
- Для каждого теста контролируются технические и продуктовые защитные метрики.
- Наблюдаемая связь между сегментом и конверсией не доказывает причину разрыва;
  решение о внедрении принимается только по результатам эксперимента.

## Необходимые события для трекинга

Для корректной оценки экспериментов необходимо фиксировать:

- показ результатов поиска и позицию каждого предложения;
- открытие карточки гостиницы;
- изменение фильтров и порядка выдачи;
- начало бронирования и переходы между его этапами;
- ошибки формы и выход из сценария;
- сохранение поиска, отправку уведомления и возврат пользователя;
- переход к финальному шагу оформления и подтверждение бронирования;
- отмену бронирования;
- фактическую стоимость поездки, если такая информация станет доступна.
